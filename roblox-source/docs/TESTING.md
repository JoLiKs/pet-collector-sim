Мутационная проверка тестов: намеренное «ломание» проверки чеков `ProcessReceipt` и session lock — тесты падают (то есть они реально что-то проверяют).

### Что покрывают тесты логики
- **DataService**: шаблон/reconcile; сохранение/загрузка; **session lock между двумя «серверами»** (ожидание, отказ, передача после release);
  «мёртвая» блокировка по таймауту; **украденная блокировка → сохранение отменено, игрок кикнут**; ретраи при сбоях DataStore; отказ DataStore на live-сервере
  (игрок не играет с пустым профилем); режим без сохранения в Studio (мгновенный при выключенных API Services).
- **Monetization**: `ProcessReceipt` (выдача, идемпотентность по `PurchaseId`, отказ сохранения → `NotProcessedYet`, повтор без дубля, неизвестный продукт, отсутствующий игрок);
  геймпассы (проверка при входе, `PromptGamePassPurchaseFinished`, отмена), Premium, множители; ограничение `PolicyService`.
- **Яйца/питомцы**: валидация аргументов (типы, NaN, отрицательные, огромные), цена, зона, расстояние, вместимость; шансы суммируются в 100%; Монте-Карло частоты;
  экипировка/слоты/продажа/«Equip Best».
- **Router/анти-спам**: rate-limit (token bucket), неизвестные действия, игрок не готов; **лимит кликов** на сервере.
- **Апгрейды, зоны, ребёрт, ежедневные награды** (стрик, сброс, VIP×2, буст удачи); **жизненный цикл игрока** (вход → leaderstats → выход со снятием блокировки).
- **PetModel**: все 35 питомцев (обычные и золотые) строятся без ошибок (на эмуляции Instance).

## 2. НЕ проверено (требуется ручной тест в Studio)

Честно: ниже — то, что **не запускалось** ни разу.

- Открытие `.rbxlx` в настоящей Studio (формат валиден по парсеру и сверке с Rojo, но «загрузилось без предупреждений» не подтверждено).
- **Внешний вид и раскладка интерфейса** (UDim2/ScrollingFrame/UIGridLayout/ViewportFrame): возможны перекрытия, неверные размеры, особенно на телефонах и узких окнах.
- Визуальный результат мира и питомцев (размеры, цвета, ориентация лица питомца, положение яиц относительно ProximityPrompt, ориентация табло лидеров).
- Реальные ответы `DataStoreService`, `OrderedDataStore`, `MarketplaceService`, `PolicyService` (эмуляция моделирует контракт, но не реальные лимиты/задержки).
- Реальные покупки Robux, `ProcessReceipt` при повторных вызовах Roblox.
- Поведение на нескольких серверах/при телепорте между местами, нагрузка 20–30 игроков, производительность (клиентская отрисовка питомцев ~7 моделей × игроки).
- Мобильное управление (удержание кнопки COLLECT, `ProximityPrompt` на тач-экранах), геймпад.
- Анти-эксплойт: проверен только по логике; реальных эксплойтов не проводилось. Проверка скорости может давать ложные срабатывания при нетипичной физике (порог 220 studs/s).
- Баланс и темп прогрессии — не обкатаны.

## 3. Чек-лист ручного теста в Studio (30–60 минут)

1. Открыть `.rbxlx` → в **Output** нет красных ошибок при старте (предупреждение про DataStore в Studio — нормально).
2. Play: появился персонаж на стартовой площадке, виден HUD (монеты/гемы/ребёрт, зона, COLLECT, меню слева).
3. COLLECT: клик/удержание/клавиша `F` — монеты растут, всплывает «+N».
4. Яйцо: подойти → `E` → окно со шансами → купить ×1 → анимация → питомец появился в **PETS** → Equip → питомец следует за игроком.
5. **Test → Local Server (2 игрока)**: питомцы одного видны другому; leaderstats у обоих.
6. UPGRADES: покупка уровня (цена списывается), скорость меняется; WORLDS: разблокировка Forest (5K), телепорт; REBIRTH: накопить 50K (или временно поднять монеты через командную строку) → ребёрт.
7. DAILY: Claim → повторно нельзя → таймер.
8. SHOP: до подстановки ID — «Soon». После подстановки ID на опубликованной игре — диалог покупки открывается; после покупки приходят уведомление и награда.
9. Выход и повторный вход — прогресс сохранён (API Services включены / игра опубликована); в **Output** нет ошибок DataStore.
10. Эмулятор устройств (**Test → Device**): телефон/планшет — интерфейс читаем, кнопки не перекрываются, COLLECT удобен.
11. Отключить API Services/интернет — игра не должна «обнулять» прогресс (на live-сервере игрока кикнет с сообщением).
12. Отдельно протестируйте покупки на **тестовом аккаунте** в опубликованной игре и проверьте поступление в Creator Hub → Analytics.

## 4. Как запустить проверки у себя

```bash
bash tools/check_all.sh            # нужны rojo, stylua, selene, luau-lsp, luau (см. rokit.toml) и python3
python3 tests/run_tests.py --luau /path/to/luau   # только тесты логики
python3 tools/build_rbxlx.py && python3 tools/validate_rbxlx.py build/PetCollectorSimulator.rbxlx
```
Для `check_all.sh` скачайте `globalTypes.d.luau` из репозитория luau-lsp (`scripts/globalTypes.d.luau`) в `tools_dl/` или рядом с проектом.

> Для Selene нужен файл стандартной библиотеки: `selene generate-roblox-std` (создаёт `roblox.yml`, в архив не включён).
